# Инструкция агенту по построению модели здания из DWG

Построй модель общего вида по новому комплекту чертежей, используя Windows,
AutoCAD 2014 ActiveX/COM, MCP и Blender bpy. Основной результат — проверенный
BLEND с происхождением геометрии, отчётом, контрольными видами и перечнем
принятых допущений. Веб-просмотр готовится отдельно из проверенного BLEND.

Следуй этапам последовательно. На каждом этапе сохраняй результат контроля.
Продолжай самостоятельную работу, пока доступны необходимые сведения.
Вопросы задавай по противоречиям, которые влияют на обязательный состав или
существенно меняют вид здания и не разрешаются доступными источниками.

## 1 Определи задание и границы результата

Зафиксируй входные данные до построения:

| Данные | Что требуется |
| --- | --- |
| Источники | Путь к DWG или корню комплекта, доступные смежные разделы |
| Назначение | Общий внешний вид; иной уровень детализации согласуется отдельно |
| Состав | Какие здания, этажи, входы, кровли и окружающие элементы нужны |
| Ограничения | Защищённые папки, правила работы с оригиналами, разрешённые выходные каталоги |
| Результаты | BLEND, отчёт, контрольные изображения; веб-просмотр при необходимости |
| Допущения | Что пользователь уже разрешил именно для нового задания |

Путь к комплекту и назначение обычно достаточны для начала обследования.
Не требуй заранее выписать все высоты, толщины и марки: сначала ищи их в
чертежах. Не требуй ручной обводки, взрыва блоков или подготовки DWG.

Согласованные упрощения предыдущего здания не распространяются автоматически
на новое. Не переносить его размеры, этажность, количества или материалы.

Выдели отдельный идентификатор задания `<case>` и отдельные каталоги описи,
конфигурации, отчётов и результатов. Не перезаписывай `evidence/spz_*` и
`artifacts/erdaut_*`: это данные предыдущего проекта. Общие исходники интеграции
можно переиспользовать, а выборки и результаты каждого задания хранить отдельно.

## 2 Соблюдай правила работы с исходниками

1. Геометрию получать непосредственно из DWG через AutoCAD COM API.
2. Открывать DWG через `open_source_drawing` с `ReadOnly=True`.
   Оставлять `ACAD_MCP_READ_ONLY=1`. Не включать редакторские инструменты.
3. Не использовать DXF, PDF, FBX, OBJ, IFC и геометрические JSON-файлы как
   промежуточный вход моделирования. Уже существующие документы можно
   учитывать как справочные материалы, если это разрешено заданием;
   геометрию модели извлекать из DWG через COM.
4. Не вызывать `Save`, `SaveAs`, `Export`, `Explode`, `Copy`, `SendCommand`;
   не исправлять контуры и системные переменные в AutoCAD.
5. Не менять файлы, атрибуты, блокировки и структуру исходной папки.
   Результаты, описи и журналы сохранять в рабочем каталоге.
6. Каждый новый BLEND и архив создавать под свободным именем.
   Сохранять предыдущую проверенную версию до проверки замены.

Если запрещены любые записи внутри исходной папки, сначала автоматически
создай побитовые локальные копии DWG и читай их через COM. Само открытие
сетевого DWG может создавать DWL/DWL2 даже при режиме чтения.
Копирование того же DWG не является конвертацией. Проверь совпадение SHA-256
оригинала и копии и сохрани соответствие путей. Сохраняй относительную
структуру связанных файлов; недоступные xref отражай как ограничение.

До чтения запиши опись: относительный путь, размер, время последней записи;
для каждого читаемого файла — SHA-256. После работы повтори сравнение.
Отдельно перечисли добавленные, удалённые и изменённые файлы. Время последнего
доступа не использовать как доказательство изменения содержания.

## 3 Проведи аудит реализации перед живым тестом

Прочитай `README.md`, `docs/INTEGRATION_RU.md`, `docs/AUDIT_2014.md` и применимые
`AGENTS.md`. Зафиксируй Git-коммит, локальные изменения и версии компонентов.
Сохраняй незакоммиченную работу пользователя.

Основные модули:

| Файл | Назначение |
| --- | --- |
| `acad_core.py`, `com_read.py`, `diagnostics.py` | Подключение, режим чтения, диагностика COM |
| `extraction.py`, `geometry.py` | Обход DWG, пакеты, координаты, кривые и блоки |
| `catalogue.py`, `interpretation.py` | Аннотации и неподтверждённые гипотезы |
| `pipeline_tools.py`, `blender_bridge.py`, `blender_worker.py` | MCP и поток COM → bpy |
| `architecture.py`, `architectural_worker.py` | Сборка по планам, отметкам и контурам |
| `overview.py`, `overview_worker.py` | Профиль общего вида реализованного здания |
| `tools/verify_blend.py`, `tools/verify_architecture.py` | Проверка сохранённого BLEND |

Пути модулей в таблице относятся к `autocad_mcp/`, кроме путей `tools/`.

Проверь фактический выбор ProgID и typelib. Унаследованное описание AutoCAD
2026 в нижней части README не доказывает совместимость с установленной версией.
Для AutoCAD 2014 ожидаются ProgID `AutoCAD.Application.19.1` и версия 19.1,
в том числе со строковым суффиксом сервисного пакета. Путь к `acax19*.tlb`
брать из установленного продукта, а не подставлять typelib 2026.

На новой машине нужны полный AutoCAD с COM, Python не ниже 3.10, pywin32,
зависимости MCP и Blender. Устанавливай Python-зависимости из `pyproject.toml`
в отдельное окружение, не снимая ограничения версий вручную. Из корня репозитория:

```powershell
py -3 -m venv .venv
& .\.venv\Scripts\python.exe -m pip install .
& .\.venv\Scripts\python.exe -m unittest discover -s tests
```

На настроенном компьютере сначала проверь существующее окружение. Успешные
offline-тесты проверяют логику адаптера, а не соединение с AutoCAD и новый DWG.

## 4 Проверь AutoCAD и MCP на реальном соединении

AutoCAD должен уже работать в той же пользовательской сессии Windows и с
сопоставимыми правами процесса. MCP не запускает AutoCAD автоматически.
Ориентир настройки — `config/codex-mcp.toml`; пути Python, Blender, репозитория
и каталога результатов заменить на фактические.

Необходимые настройки сервера:

```text
ACAD_MCP_READ_ONLY=1
ACAD_MCP_PROGID=AutoCAD.Application.19.1
ACAD_MCP_EXPECTED_VERSION=19.1
ACAD_MCP_TYPELIB=<фактический путь к acax19*.tlb>
ACAD_MCP_BLENDER=<фактический путь к blender.exe>
ACAD_MCP_OUTPUT_ROOT=<рабочий каталог результатов>
PYTHONUTF8=1
```

Переменные уже запущенного MCP-процесса не изменяются от установки переменных
в другом терминале. После изменения конфигурации перезапусти MCP-хост и проверь
доступные инструменты и ответ нового процесса. Не сообщай о перезапуске по
одному факту редактирования конфигурации.

Последовательно вызови:

```text
autocad_status({})
diagnose_compatibility({})
open_source_drawing({"path": "<полный путь к рабочему DWG>"})
get_active_drawing_info({})
```

Проверь `ok`, фактическую версию, полный путь документа, `ReadOnly`, `INSUNITS`
и чтение обязательных свойств. Если нужный файл уже открыт для редактирования,
не закрывай его с потерей пользовательской работы. Открой отдельную побитовую
копию для чтения или запроси решение, если это невозможно.

`MK_E_UNAVAILABLE` может означать недоступность COM ROT из другой сессии или
изоляции. Сначала проверь контекст запуска и права. Отсутствие соединения
не подменять фиктивной геометрией или заявлением об успешной совместимости.
При временной занятости AutoCAD дождись завершения команды; не запускай
параллельные COM-обходы. В проекте есть ограниченные повторы COM-чтения.

При адаптации API используй `tools/acax_probe.py`, `tools/check_flagged_methods.py`
и `tools/check_extraction_api.py`. Проверка typelib и unit-тесты дополняют,
но не заменяют живой тест на новом комплекте.

## 5 Обследуй комплект и выбери действующие решения

Составь реестр файлов и листов: раздел, номер, название, ревизия, назначение,
путь, SHA-256, связь с другими листами. Ищи планы этажей, разрезы, фасады,
план кровли, ведомости окон и дверей, узлы, опалубочные планы и каркас.

Для первичного чтения используй:

```text
inspect_drawing_annotations({"path": "<DWG>", "max_items": 1000})
list_layers({})
list_blocks({})
list_layouts({})
```

Последние три инструмента читают активный документ: перед ними проверь его путь.
Если активен другой DWG, используй manifest полного скана нужного документа
и обращения к его COM-объекту; не присваивай ему слои и блоки чужого файла.
В `inspect_drawing_annotations` проверяй `counts` и `truncated`: первые 1000
записей не доказывают полноту. Если ответ усечён, изучай полный COM-каталог
или пакетный обход. Этот инструмент не предоставляет постраничного продолжения
аннотаций; таблицы при необходимости читай через `catalogue.py` в памяти.

Один ModelSpace может содержать несколько этажей, фасады, детали и старые
варианты. Скрытый слой, состояние viewport, дата изменения или имя «новый»
не определяют действующее решение. Не включай все контуры файла в одну модель.
Отдели области изображений по заголовкам, осям и ссылкам на листы. Геометрия
фасада или разреза, нарисованная в плоскости XY, не является плановым контуром
для вертикальной экструзии.

Приоритет источников устанавливай по штампам, ревизиям, назначению и связям
листов. Конструктивные размеры сверяй с КЖ, изделия — с актуальными узлами и
ведомостями, расположение — с планами, высоты — с разрезами и отметками.
Это способ сопоставления, а не безусловное правило разрешения любых коллизий.
Реальные противоречия сохраняй в журнале с обоими источниками.

## 6 Извлеки геометрию полностью и пакетами

Для общего обследования используй `scope="all"`: ModelSpace и блоки листов.
`scope="model"` допустим, если область явно определена. Видовые экраны листов
не должны создавать вторую копию ModelSpace.

```text
start_geometry_scan({"path": "<DWG>", "scope": "all"})
read_geometry_batch({"scan_id": "<из ответа>", "page": 0,
                     "limit": 100, "max_bytes": 256000})
```

Продолжай по `next_page` до `done=true`. `limit` ограничивает фрагменты,
а не обязательно целые сущности. Диапазон `max_bytes` — 4096…1000000;
не повышай размер пакетов без необходимости. Большая запись может занимать
несколько пакетов.

Используй `autocad_mcp.extraction.RecordAssembler`: собирай `json_fragment`
по `record_id`, строго проверяя `offset` и `total_chars`. Не разбирай обрезанную
запись как готовую сущность. В конце должны отсутствовать незавершённые записи,
а ответ должен содержать `source_unchanged=true` и итоговый SHA-256.

Курсоры последовательные, повтор обработанной страницы отвергается. При
потере ответа с неизвестным состоянием курсора, изменении источника или
перезапуске MCP закрой доступный старый скан и начни новый. Не смешивай
фрагменты разных сканов. После завершения вызывай `close_geometry_scan`.
Сканы находятся в памяти процесса; одновременно допускается до восьми.

Не допускай редактирования читаемого документа во время обхода. Проверяются
путь, `ReadOnly`, `DBMOD`, количества сущностей и хеш файла; COM не предоставляет
транзакционный снимок всех изменений памяти AutoCAD.

Учитывай линии, 2D/3D-полилинии, bulge, дуги, окружности, эллипсы, доступные
сплайны и mesh, блоки с вложениями, атрибуты, тексты, размеры и отметки.
Для каждой записи сохраняй тип, слой, путь handles и статус. Пустой результат,
`unsupported` и ошибка чтения — разные состояния.
`record['id']` уникален в контексте обхода одного документа; для связи между
файлами используй также идентификатор DWG и SHA-256, поскольку handles повторяются.

Обязательные ограниченные случаи:

- ACIS `3DSolid` в ActiveX 2014 не имеет общего проверенного чтения граней;
  метрики и bounding box не заменяют точную геометрию тела.
- `PolyfaceMesh.Faces` в используемой typelib доступно для записи;
  не объявляй перенос топологии успешным по одним вершинам.
- Xref с отсечением, MInsert, proxy, Hatch, MLeader и другие неподдержанные
  объекты отражай явно. Критичность определяй по их роли в выбранной модели.
- Точное содержание аннотации не означает точное воспроизведение её шрифта,
  размерной графики или выносок. Preview сплайна не доказывает глобальный
  допуск аппроксимации, если такой оценки нет в адаптере.

Если нужная геометрия недоступна при COM-only ограничении, найди другое её
изображение в DWG или задай предметный вопрос. Не создавай подменяющий куб
по bounding box и не переходи к конвертации молча.

## 7 Нормализуй единицы и системы координат

Единицы устанавливай по `INSUNITS` и контрольным размерам. При неизвестных
единицах `mm_per_unit=null`; масштабированное построение блокируется.
Override `mm_per_unit` передавай только с `units_evidence` и проверенным
основанием. Надпись «масштаб 1:100» не означает, что координаты ModelSpace
нужно делить или умножать на 100.

В новом потоке геометрия записи остаётся в исходных единицах определения,
`world_matrix` переводит её в WCS миллиметры. Преобразование вершины:

```text
p_wcs_mm = world_matrix × [x, y, z, 1]
p_building_mm = T_plan_to_building × p_wcs_mm
p_blender_m = p_building_mm / 1000
```

Матрицы применяются к столбцам. Не умножай `mm_per_unit` второй раз после
`world_matrix`. Для плана высоту архитектурного элемента назначай отдельно
по его основанию и верху; исходное Z=0 у плана не является высотой этажа.
Формула относится к координатам, уже нормализованным адаптером сущности:
для полилиний `vertices` уже учитывают OCS, а `ocs_vertices` сохраняют исходник.
Используй `geometry.world_geometry` для готовой мировой геометрии; не повторяй
его преобразования и не применяй к `ocs_vertices` формулу без перевода OCS.

Проверь OCS с `Elevation` и `Normal`, начало определения блока, поворот,
неравномерный и отрицательный масштаб, вложенные вставки. Не применяй
`InsUnitsFactor` повторно поверх уже учтённого масштаба вставки. Dynamic block
читай по фактическому `Name`, сохраняя `EffectiveName` для анализа. Слой 0
наследует слой вставки. Текущую UCS сохраняй как метаданные, без повторного
преобразования готовой WCS-геометрии.

Углы нового потока — радианы; у унаследованных инструментов рисования —
градусы. Сравнивай длину дуги и преобразованную геометрию с учётом масштаба;
после неравномерного масштабирования окружность может стать эллипсом.

Совмести планы этажей и разделов по осям и устойчивым опорным точкам.
По возможности используй не менее трёх неколлинеарных точек и независимые
контрольные расстояния. Сохрани матрицу совмещения, выбранное начало,
остаточные ошибки и связь условного нуля с абсолютной отметкой, если она известна.
Не сдвигай каждый контур отдельно ради визуального совпадения.
Для далёких координат используй локальное начало с обратимым преобразованием.

## 8 Составь реестр параметров и элементов

`interpret_geometry` принимает до 1000 готовых записей и выдаёт гипотезы.
Названия слоёв и блоков помогают искать элементы, но сами по себе не доказывают
материал, назначение, высоту или количество физических изделий.

Если стены представлены отдельными линиями, сначала установи, являются ли
они границами или осевыми линиями. Замкнутые цепочки допускаются при доказанной
топологии; существующий анализ распознаёт циклы графа степени 2 без продления
линий. Для осевой линии толщину требуется подтвердить отдельно. Сложные ветвления
и пересечения требуют отдельного алгоритма; не подменяй их произвольной обводкой.

Для каждого параметра сохрани значение, единицу, статус, источник с SHA-256,
лист и handles, способ получения и зависимые элементы. Используй различимые
состояния в реестре и отчёте:

| Статус | Основание |
| --- | --- |
| Подтверждён | Однозначный размер, геометрия или запись действующего источника |
| Вычислен | Формула и ссылки на подтверждённые исходные величины |
| Принятое упрощение | Конкретное разрешение пользователя и область применения |
| Неизвестен | Достаточного основания нет; значение не подставляется как факт |
| Противоречие | Несогласованные значения и источники, решение ещё не установлено |

Это логические статусы рабочего реестра: сопоставь их фактическим полям
`confirmed`, `source_ids`, `evidence_status`, `unresolved` выбранного профиля.
Не выставляй `confirmed=true` для обхода валидатора. Если профиль не умеет
сохранять принятое допущение отдельно от факта, сначала исправь эту часть.

Обязательные группы параметров: сетка, единицы и начало; уровни этажей;
верх/низ плит и их толщины; границы стен; колонны и балки; проёмы и изделия;
кровля, парапет и карниз; входы и лестницы в пределах задания.
Различай чистый пол, верх конструктивной плиты и опирание стены.
Для окна отдельно фиксируй ширину/высоту проёма, изделия, монтажные зазоры,
подоконную отметку и привязку к фасаду.

Составь реестр ожидаемых физических элементов по категориям, этажам и маркам.
Один объект AutoCAD, одна оконная сборка и один mesh Blender не обязаны
соответствовать друг другу по количеству. Дедупликацию выполнять по
совпадающему положению и геометрии с сохранением всех исходных ссылок.
Одинаковые блоки в разных местах не объединять.

## 9 Подготовь проверочную геометрию и профиль нового проекта

Сначала создай проверочные BLEND нужных листов через `build_blender_model` без
семантических правил. Они содержат исходную геометрию и доказательства чтения;
эта сцена ещё не является объёмной моделью здания.

```text
build_blender_model({"path": "<DWG>", "output": "<case>/plan_reference.blend",
                     "scope": "all", "tolerance_mm": 0.25})
```

Значение `output` относится к `ACAD_MCP_OUTPUT_ROOT`; имя должно быть свободным.
Указанный допуск — пример вычислительного допуска, применявшийся в этом проекте.
Для нового здания выбери и зафиксируй подходящий допуск до проверки.

Поток передачи: DWG → COM → MCP-обработчик → анонимный stdin Blender → BLEND.
Записи источника встраиваются внутрь BLEND; отдельный геометрический файл
для обмена не создаётся. Для повторной сборки можно читать эти записи в память,
предварительно проверив хеши соответствующих DWG. Если DWG изменился, сначала
повторить извлечение через COM.

Для простого подтверждённого горизонтального замкнутого контура доступны
`rules`: `source_id`, `category`, `confirmed`, `evidence`, а также `height_mm`
и `base_z_mm` с полями `value`, `confirmed`, `source`. Общая экструзия сама
не создаёт отверстия плит и оконные/дверные проёмы.

Для полной сборки подготовь проектный JSON с выборками handles, путями к
проверочным BLEND, хешами, параметрами, источниками и нерешёнными вопросами.
Геометрические записи в этот файл не выгружай. Текущие поля проекта:

- `floors`: имя, `source_blend`, `title_id`, `base`, `wall_top`;
- `column_top`, `slabs`, `datum_absolute_m`, `tolerance_mm`;
- `evidence_drawings`, `unresolved`;
- для профиля общего вида — `profile`, `accepted_simplifications`,
  `base_model`, `overview_sources`, `overview_parameters`.

Параметры базовой архитектурной сборки используют `value_mm`, `confirmed`
и `source_ids`. Это отличается от формата `rules` общего построителя.
Точный набор вложенных полей проверяй в `validate_project` и выбранном worker.

### Привязки которые обязательно заменить

Текущая архитектурная сборка не является универсальным распознавателем.
Не запускай её на новом здании простой заменой пути DWG. Вынеси в новый
профиль или параметризуй следующие проектные зависимости:

| Участок | Что привязано к исходному зданию |
| --- | --- |
| `architecture.plan_frame` | 24 условных блока колонн 400×400, сетка 30000×12900, поиск около заголовка |
| `architecture.classify_layer` | Конкретные названия `KG_*` |
| `overview.window_gaps` | Отбор разрывов шириной 1050 мм |
| `architectural_worker.py`, `overview_worker.py` | Выборки контуров, handles, уровни, этажи, кровля и входы |
| `tools/prepare_overview_project.py` | Пути, состав источников и допущения одного проекта |
| `tools/stage_spz_sources.py`, `tools/verify_spz_unchanged.py` | Имена описей и каталоги конкретного исследования |
| `tools/verify_architecture.py` | Оконные handles, 37 окон, 22 колонны и верх +9.670 |
| `tools/export_web_model.py` в просмотрщике | Заголовок, некоторые количества, габариты и набор категорий |

Сейчас архитектурные workers также ограничивают часть входов `mm_per_unit=1`.
Для других единиц адаптируй обработку к нормализованным WCS-миллиметрам;
не объявляй исходные единицы миллиметрами ради прохождения проверки.

Изменяй проектные правила вместе с независимой проверкой, сохраняя общий
поток COM. Для каждого нового правила подготовь контрольный случай из нового
комплекта; для изменённой сложной геометрии добавь подходящие тесты.

## 10 Построй объёмную модель через bpy

Строй реальные mesh-объекты с измеряемой геометрией. Сцену настрой в метрах:
`unit_settings.system='METRIC'`, `scale_length=1`. Не ограничивайся визуальной
сменой подписи единиц: пересчитай координаты из миллиметров.

Раздели модель по этажам и категориям: каркас, плиты, стены, утепление,
облицовка, окна, двери, кровля, входы и неопределённые конструкции.
Камеры, свет, земля и фон помести в отдельную презентационную коллекцию,
исключённую из подсчётов и измерений здания.

Порядок построения:

1. Каркас и плиты по выбранным конструктивным планам, включая подтверждённые
   отверстия и толщины. Архитектурный символ колонны не заменяет конструктивный
   профиль без проверки. Не объединяй этажи в непрерывную опору без основания.
2. Стены и фасадные слои по контурам. Для открытого контура не достраивай
   неизвестное ребро. Совпадающие исходные конечные вершины могут доказывать
   замыкание при `Closed=False`; ненулевой зазор сам по себе не исчезает от допуска.
3. Проёмы и заполнения. Восстанови подоконные и надпроёмные участки; вырезай
   отверстие через все пересекаемые непрозрачные слои. Если блоки отсутствуют,
   используй подтверждённые разрывы стен вместе с марками и ведомостью.
   Не добавляй окна только для достижения ожидаемого количества.
4. Полы, кровля, парапеты и карнизы с отдельными отметками. Разуклонку и состав
   кровли упрощать только в согласованных границах, сохраняя происхождение чисел.
5. Крыльца, навесы, ступени и другие видимые элементы задания. Проверяй уровни
   площадок, число подъёмов и сопряжение с дверями; высоты не брать по аналогии.
6. Материалы и внешний вид. Неподтверждённый материал показывай нейтрально;
   приближённый цвет не выдавай за проверенную колориметрию.

Прямоугольная плита с ортогональными отверстиями поддержана существующим
алгоритмом. Для наклонных, криволинейных, пересекающихся или выходящих за
наружную границу отверстий требуется отдельная проверенная реализация.
Не заменяй сложную форму её габаритным прямоугольником без принятого упрощения.

Каждому элементу назначь уникальный `element_id`, исходные `source_id` и
идентификацию DWG/ревизии, категорию, этаж, источники размеров и статус.
Деталям окна дополнительно назначь общий идентификатор сборки.
Сохраняй связь один-ко-многим и несколько-источников-к-одному.

После адаптации профиль вызывается существующим MCP-инструментом:

```text
assemble_architectural_model({"project_path": "<полный путь к project.json>",
                              "output": "<case>/building_v001.blend"})
```

Базовый worker и профиль `overall_view` выбираются в `architectural_bridge.py`.
Для нового типа профиля сначала реализуй его маршрутизацию: произвольная
строка `profile` сама по себе не создаёт новый алгоритм.

## 11 Проверь размеры происхождение и полноту

Проверяй модель при построении и после сохранения. Разделяй три результата:
точность переноса координат, полноту обязательного состава и достоверность
архитектурной интерпретации. Прохождение одного не доказывает остальные.

Обязательный контроль:

1. Сравни сохранённые мировые вершины, габариты и отметки с исходными COM-данными
   и подтверждёнными параметрами. Для блока проверяй составную матрицу и положение,
   а не только размеры его общей рамки.
2. Проверь оси, расстояния, повороты, общий верх/низ и отсутствие ошибки масштаба
   в 1000 раз. Консервативный `GetBoundingBox` не всегда равен тесной рамке;
   свободный зазор рамки не объявлять ошибкой координат.
3. Для объёмных элементов проверь замкнутость сетки, толщину, высоту и применимый
   аналитический объём. Для плит: площадь контура минус отверстия, умноженная
   на толщину; допуск объёма учитывать отдельно от линейного допуска.
4. Проверь сквозность выбранных отверстий и оконных проёмов контрольными лучами.
   Один луч не является доказательством отсутствия всех коллизий; дополнительно
   осмотри проём целиком и проверь пересекаемые слои.
5. Сопоставь ожидаемые элементы с построенными по этажам, маркам, категориям
   и идентификаторам сборок. Зафиксируй пропуски, дубликаты и исключения.
   Не сравнивай число деталей окон с числом окон в ведомости.
6. Независимо повторно получи ключевые размеры из исходной COM-геометрии,
   в том числе встроенной в BLEND. Проверка mesh только против массива вершин,
   созданного тем же построителем, не проверяет правильность его интерпретации.
7. Сопоставь проекции с планами, фасадами и разрезами в их системах координат.
   Автоматическое наложение требует явного преобразования вида; одна картинка
   общего вида не подтверждает совпадение.
8. Повторно проверь SHA-256 использованных источников и защищённую папку.

Создай общий вид, фасады, вид кровли, планы этажей со скрытыми верхними
элементами и виды спорных узлов. Осмотри рендеры, а не только их наличие.
Скрытие объекта для контрольного вида не означает его отсутствие из модели.

В отчёте сохрани: версии и Git-коммиты, источники/хеши, преобразования и единицы,
реестр параметров, принятые решения, ожидаемые и фактические количества,
максимальные ошибки и допуски, неподдержанные типы, пропуски, проверки проёмов,
контрольные изображения и оставшиеся ограничения.

Не устанавливай `semantic_building_verified=true` или `full_fidelity=true`
по факту успешного выполнения скрипта. Для общего вида допустим проверенный
результат с явно сохранёнными упрощениями и этими признаками `false`.

## 12 Повторно открой итоговый BLEND

Открой именно сохранённый файл новым процессом Blender с `--disable-autoexec`
и ненулевым кодом выхода при ошибке Python. Повтори измерения, сверку количества,
проверку исходных хешей и независимые проверки ключевых элементов.

Пример запуска после адаптации верификатора нового проекта:

```powershell
& $blender --background $finalBlend --disable-autoexec --python-exit-code 3 --python tools/verify_architecture.py
```

`$blender` и `$finalBlend` должны содержать фактические полные пути.
Для проверочной сцены исходной геометрии используется `tools/verify_blend.py`.
Существующий `verify_architecture.py` требует замены проектных привязок,
перечисленных выше; успешный тест старого здания не проверяет новое.

В итоговом BLEND сохраняй исходные COM-записи и аудит. Имеющиеся имена
текстовых блоков:

- `AutoCAD source provenance.jsonl.zlib.base85` — исходный поток;
- `AutoCAD verification report.json.zlib.base85` — контроль переноса;
- `Architectural reconstruction audit.json.zlib.base85` — архитектурная сборка;
- `AutoCAD combined source provenance.json.zlib.base85` — источники общего вида.

Набор блоков зависит от вида результата. Сжатые записи служат происхождением
геометрии и основанием воспроизводимости, а не поводом публиковать внутренние
пути и документы во внешнем просмотрщике.

## 13 Подготовь веб просмотр при необходимости

Просмотрщик выделен в [самостоятельный репозиторий](https://github.com/AndreyAdamenko/darbaza-5800-1.3-erdaut-model-viewer)
(локальная папка `AutocadModelViewer`).
На машине исходного проекта он находится рядом с `AutocadMCP`;
на другой машине путь необходимо определить явно. Его `README.md` описывает
локальный запуск, сборку, переносимый архив и Docker.

Из проверенного BLEND автоматически получи производный GLB и `model.json`
через `tools/export_web_model.py` репозитория просмотрщика. Это этап доставки
готовой модели в браузер после построения BLEND; DWG не конвертируется.
Экспортер требует встроенный аудит и не является экспортом произвольного BLEND.

Перед экспортом нового здания убери проектные константы из manifest и проверь
соответствие категорий/свойств новому профилю. Экспортируй только модельные
объекты и разрешённые свойства. Полные COM-журналы, пути и исходные документы
в веб-ресурсы не включай. SHA-256 исходного BLEND до и после должен совпасть.

Пример из корня репозитория просмотрщика:

```powershell
& $blender --background $finalBlend --disable-autoexec --python-exit-code 3 --python tools/export_web_model.py -- --output "$PWD/assets"
npm ci
node verify-model.mjs
npm run build
python tools/serve_viewer.py --open
```

Каталог `assets` должен быть свободен от прежней пары модели. Перед обновлением
сохрани предыдущую пару отдельно. Верификатор сверяет SHA-256, идентификаторы,
количества, размеры, отметки и преобразование Blender Z-up → glTF Y-up.
Проверь в браузере загрузку, ракурсы, категории, скрытие кровли, отсечение,
выбор элемента, размеры, PNG и ошибки консоли на новой модели.

Для локального просмотра сервер слушает `127.0.0.1`. Docker на корпоративном
сервере — отдельное развёртывание. `docker compose config` проверяет конфигурацию;
о работающем контейнере можно говорить только после фактического запуска и
HTTP-проверки. Исходный код и проектные модели хранить раздельно; публикацию
внешнего сайта или передачу модели выполнять в рамках разрешённого назначения.

## 14 Действуй при нехватке данных

Сначала прочитай связанные листы и смежные разделы, затем сформулируй один
конкретный вопрос с двумя источниками и последствиями вариантов.
Не останавливай независимые части работы из-за одного нерешённого элемента.

Для общего вида блокируют завершение, например: неустановленный масштаб,
несовместимая сетка без объяснимого преобразования, неизвестная этажность или
основные высоты, разные действующие варианты габарита/фасада без принятого
приоритета, недоступная обязательная геометрия.

Второстепенные глубины профилей, фурнитуру, скрытые соединения и материалы
можно упростить в пределах действующего согласования. Запиши значение,
причину, область применения и статус; неизвестный параметр не превращается
в подтверждённый после принятия упрощения. Если разрешения нет, подготовь
конкретный вариант для согласования. Не придумывай типовые высоты этажей
или толщины перекрытий для обхода блокирующей неопределённости.

## 15 Передай результат и инструкцию осмотра

Работа завершена, когда обязательный состав задания учтён, сохранённый BLEND
прошёл повторное открытие и проверку, исходники сохранены, а существенные
неопределённости разрешены либо явно приняты для общего вида.

Передай пользователю ссылки на итоговый BLEND, отчёт, контрольные изображения
и при наличии просмотрщик/архив. Укажи фактически построенный состав,
максимальную измеренную ошибку с допуском и отдельный список допущений.
Объясни, как открыть файл, выбрать камеру, скрыть презентационную коллекцию
и измерить элемент. Не заставляй пользователя искать результат среди версий.

Для воспроизведения сохрани профиль нового проекта, источники параметров,
версии программ, Git-коммиты, команды запуска и проверки. Конфигурации и код
не должны требовать ручного экспорта или редактирования DWG.

Фактический ориентир предыдущего проекта: 1 121 объёмный объект, 37 оконных
сборок, 22 колонны; отдельное открытие Blender и геометрические проверки
